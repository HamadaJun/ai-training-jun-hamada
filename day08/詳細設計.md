# Day 08 詳細設計書

## 1. 概要

Day 08 は、処理失敗時のリトライとフォールバックを LangGraph で制御するCLIプログラムである。
失敗回数と処理ステップ数に上限を設け、無限ループを防止する。

対象ファイル：`day08/app.py`
起動方法：`python -m day08.app`

## 2. 目的

- 処理失敗時に同じ処理を上限付きで再試行する
- リトライ上限に到達した場合に代替処理へ切り替える
- 全体のステップ数を制限し、無限ループを防止する
- 失敗種別とエラー履歴を state に保持する

## 3. CLI仕様

| オプション | 必須 | 型 | デフォルト | 制約 | 説明 |
|---|---:|---|---:|---|---|
| `--text` | Yes | 文字列 | なし | 空文字不可 | 処理対象の入力 |
| `--max-steps` | No | 整数 | `10` | `1〜50` | グラフ全体の最大実行ステップ数 |
| `--max-retry` | No | 整数 | `1` | `0〜5` | 失敗処理の最大リトライ回数 |

### 終了コード

- `0`：正常終了
- `2`：CLI入力不備
- `1`：実行失敗、依存関係不足、ステップ上限到達など

## 4. state設計

`GraphState` は LangGraph のノード間で共有する状態である。

| キー | 型 | 内容 | 更新箇所 |
|---|---|---|---|
| `input` | `str` | ユーザー入力 | グラフ開始時 |
| `status` | `str` | `success`、`retry`、`fallback` | `attempt` |
| `output` | `str` | 最終的な処理結果 | `attempt` または `fallback` |
| `errors` | `List[str]` | 発生したエラー履歴 | `attempt` |
| `steps` | `int` | 実行済みステップ数 | `attempt` |
| `retries` | `int` | 実行済みリトライ回数 | `attempt` |
| `failure_kind` | `str` | 失敗種別 | `attempt` |

認証情報、DB接続情報、APIキーなどは state に保存しない。

## 5. ノード設計

### 5.1 `attempt`

処理の中心ノード。実行ごとに `steps` を1増やし、入力内容に応じて成功・リトライ・フォールバックを判定する。

#### ステップ上限

`steps > max_steps` の場合、`RuntimeError` を送出する。これによりグラフの無限ループを停止する。

#### JSONパース失敗の再現

入力に `不完全なjson` が含まれる場合、JSONパース失敗として扱う。

- `retries < max_retry`：`status=retry`、`retries` を1増加
- `retries >= max_retry`：`status=fallback`
- エラー内容を `errors` に追加

#### 検索ヒットなしの再現

入力に `存在しない情報` または `検索ヒットなし` が含まれる場合、検索結果なしとして扱い、`status=fallback` にする。

なお、現在の実装は実際のWeb検索・DB検索・ベクトル検索を行わず、入力キーワードで失敗ケースをシミュレーションする。

#### 通常成功

上記の失敗条件に該当しない場合、`status=success` として処理結果を `output` に保存する。

### 5.2 `retry`

リトライ回数、最大リトライ回数、失敗種別をログに出力する。処理結果は変更せず、`attempt` に戻す。

### 5.3 `fallback`

失敗種別に応じて代替結果を作成し、`output` に保存する。

- JSON失敗：簡易形式で処理した旨を返す
- 検索結果なし：別のキーワードを指定するよう案内する

処理後は `END` へ遷移する。

## 6. グラフ構成

```text
START
  |
  v
attempt
  |-- status=success ------> END
  |-- status=retry --------> retry --+
  |                                  |
  |                                  +--> attempt
  |-- status=fallback -----> fallback --> END
```

## 7. 条件分岐

`route` が `state["status"]` を読み取り、次の遷移先を返す。

| status | 遷移先 | 意味 |
|---|---|---|
| `success` | `END` | 正常終了 |
| `retry` | `retry` | リトライ処理後に再試行 |
| `fallback` | `fallback` | 代替処理へ移行 |

未知の状態は `fallback` に遷移する。

## 8. 上限設計

### `max-retry`

失敗処理の再試行回数を制限する。初回実行はリトライ回数に含めない。
たとえば `--max-retry 2` の場合、初回実行と2回の再試行、合計3回まで実行する。

### `max-steps`

グラフ全体の `attempt` 実行回数を制限する。`max-retry` より優先される全体上限であり、上限到達時はエラー終了する。

## 9. ログ設計

ログは処理状況の確認に使用する。

- 開始時：`max-steps` と `max-retry`
- 成功時：ステップ数と成功状態
- 失敗時：ステップ数と失敗種別
- リトライ時：現在のリトライ回数、上限、失敗種別
- フォールバック時：失敗種別

ユーザー入力全体や認証情報はログに出力しない。

## 10. エラー処理

| 条件 | 処理 | 終了コード |
|---|---|---:|
| `--text` 未指定または空 | エラーを標準エラーへ出力 | `2` |
| `max-steps` が範囲外 | エラーを標準エラーへ出力 | `2` |
| `max-retry` が範囲外 | エラーを標準エラーへ出力 | `2` |
| LangGraph未導入 | エラーを標準エラーへ出力 | `1` |
| ステップ上限到達 | エラーを標準エラーへ出力 | `1` |
| リトライ上限到達 | フォールバックして処理継続 | `0` |

## 11. 実行例

### 通常成功

```powershell
python -m day08.app --text "〇〇について教えて"
```

### JSON失敗とリトライ

```powershell
python -m day08.app --text "不完全なJSONを返して" --max-retry 2
```

初回実行後に2回リトライし、リトライ上限到達後にJSON用フォールバックへ進む。

### 検索ヒットなしとフォールバック

```powershell
python -m day08.app --text "存在しない情報について教えて"
```

検索結果なしとして、別キーワードを指定するメッセージを返す。

### ステップ上限

```powershell
python -m day08.app --text "不完全なJSONを返して" --max-steps 1 --max-retry 5
```

全体上限が先に到達した場合、無限にリトライせず実行失敗として終了する。

## 12. 既知の制約

- JSON生成・検索処理は実サービスに接続せず、入力キーワードで失敗をシミュレーションしている
- `fallback` は簡易メッセージを返すだけで、実際の再検索や質問生成は行わない
- LangGraphの依存ライブラリから互換性に関する警告が表示される場合があるが、処理結果とは別の通知である
